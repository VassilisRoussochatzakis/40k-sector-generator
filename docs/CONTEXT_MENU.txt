# CONTEXT_MENU — Builder Right-Click Menus (Sector + System Views)

Scope: builder binary only (`sectorforge-builder`). Adds right-click context
menus to the sector hex map (MAP tab) and to a per-system "in-system" map
widget (SYSTEM tab). Viewer, exporter, and CLI binaries are out of scope.

This document is a build guide for an LLM agent. It assumes the agent has
read [CLAUDE.md](../CLAUDE.md), [docs/BUILDER_REQS.txt](BUILDER_REQS.txt), and
the files referenced under "Touchpoints" before editing.

---

## 0. Why context menus

The builder already exposes ~40 operations across the SYSTEM, ROUTES,
REGIONS, FACTIONS, CONFLICT, ORBITAL, ARCHETYPE, CONTROL panels. Reaching
them requires (1) selecting the entity, (2) switching tabs, (3) scrolling to
the right collapsing-header section. A right-click menu lets a user perform
the most common follow-up actions in-place without losing map context. This
is purely an interaction-layer feature: every menu item must dispatch
through an existing or new `BuilderCommand` so the undo log and validation
pump continue to work.

---

## 1. Non-goals

- No new persisted data model. Menu state is transient and in-memory only.
- No global "command palette" — that is a separate feature.
- No changes to viewer (`sectorforge-viewer`) or CLI surface.
- No re-implementation of `egui::menu::menu_button`; reuse the egui idioms.
- No keyboard-only shortcuts in v1 (covered in §15 — Future work).
- No localisation pass — strings are English literals matching the existing
  tab labels (`SCREAMING_CASE` for verbs, sentence case for tooltips).

## 4. UX specification

### 4.1 Trigger gesture

- **Primary trigger:** `Response::secondary_clicked()` on the map canvas.
- **Modifier-aware:** `Ctrl + secondary_clicked` opens the menu even when
  `MapTool::RegionPaint` is armed (the brush already consumes right-click
  for erase — see [map.rs:286](../builder/src/builder/panels/map.rs#L286)).
- **Suppress while dragging:** if `state.drag_system.is_some()` or
  `state.rect_select.is_some()`, ignore the secondary click.
- **Suppress while menu is open:** only one menu at a time; second secondary
  click closes any open menu first, then opens a new one at the new pos.

### 4.2 Menu appearance

- Render with `egui::Area` (anchored at the cursor) + a containing
  `egui::Frame::menu(ui.style())`. **Do not** use `Window` (menus must not
  be resizable, draggable, or collapsible).
- The menu must stay within the viewport — clamp its top-left so the area's
  rect fits in `ui.ctx().screen_rect()`. If the menu would extend past the
  right or bottom edge, flip it to anchor at the opposite corner of the
  cursor.
- Item style: `selectable_label` with monospace font, `2.0` vertical spacing,
  `8.0` horizontal padding. Disabled items use `ui.add_enabled(false, …)`.
- Submenus via `egui::menu::menu_button` for grouped destinations
  (e.g. "Open in tab ▸ {Routes, Subsectors, Regions}").

### 4.3 Dismiss rules

- Click outside the area → dismiss.
- `Escape` → dismiss (read via `ui.input(|i| i.key_pressed(Key::Escape))`).
- Window loses focus → dismiss (`ui.ctx().input(|i| i.focused) == false`).
- Item activation → run command, then dismiss.

### 4.4 Hover preview

While the menu is open, paint a `paint_system_rings` overlay (yellow,
2.0 px) around the context entity so the user can confirm the click hit
the intended target. Same overlay applies to the SystemView (highlight
the contextual planet ring).

## 5. State plumbing

A single new struct on `BuilderState` carries the open-menu payload. All
context resolution happens at click-time; the struct just records "menu is
open, here's where, here's what it points at".

### 5.1 New types ([builder/src/builder/state/types.rs](../builder/src/builder/state/types.rs))

```rust
/// §CTX1 — open context menu on the MAP tab. None when no menu is open.
#[derive(Debug, Clone)]
pub struct SectorContextMenu {
    pub screen_pos: egui::Pos2,
    pub target: SectorMenuTarget,
}

#[derive(Debug, Clone)]
pub enum SectorMenuTarget {
    EmptyHex { coord: HexCoord },
    System { id: SystemId, coord: HexCoord },
    Route { id: RouteId, near_coord: HexCoord },
    RegionHex { region: String, coord: HexCoord },
    SubsectorBorder { subsector: String, coord: HexCoord },
    MultiSelection { ids: Vec<SystemId> },
}

/// §CTX2 — open context menu on the in-system map (SYSTEM tab).
#[derive(Debug, Clone)]
pub struct SystemContextMenu {
    pub screen_pos: egui::Pos2,
    pub target: SystemMenuTarget,
}

#[derive(Debug, Clone)]
pub enum SystemMenuTarget {
    Star { system: SystemId },
    World { system: SystemId, world: WorldId, orbit: u8 },
    EmptyOrbit { system: SystemId, orbit: u8 },
    Background { system: SystemId },
}
```

Add two fields to `BuilderState`:

```rust
pub sector_context_menu: Option<SectorContextMenu>,
pub system_context_menu: Option<SystemContextMenu>,
```

Both initialised to `None` in `BuilderState::new_blank` and `default_config`.

### 5.2 Selection vs context

Opening the menu **does not** mutate selection. The context target is
ephemeral — distinct from `selected_system_id` / `selected_systems`. This
matches existing modal patterns (`PendingPlace`, `PendingRename`).

Exception: items labelled "Focus" or "Open in …" call `focus_entity` after
running, which does mutate selection. That is the user's explicit intent.

### 5.3 Menu lifecycle

```
secondary_clicked → resolve_context() → state.sector_context_menu = Some(…)
                                          ↓
                            show_context_menu(ctx, state) renders Area
                                          ↓
                  item activated → run command, then `state.sector_context_menu = None`
                  dismiss        → `state.sector_context_menu = None`
```

## 6. Menu schemas

Every item lists: **label** (display string), **enabled-when** (gate), and
**action** (the `BuilderCommand`, helper fn, or focus call it triggers).
The order below is the render order.

### 6.1 Sector map — empty hex

| Item | Enabled when | Action |
|------|--------------|--------|
| `PLACE SYSTEM HERE…` | always | `state.pending_place = Some(PendingPlace { coord, name: "Sys-N" })` (reuses existing dialog) |
| `PAINT REGION HERE` | `state.selected_region_id.is_some()` | `paint_region_at(state, coord, false)` |
| `ERASE REGION HERE` | hex belongs to a region | `state.erase_region_hex(&id, coord)` |
| —–-divider—– | | |
| `START PARTIAL REGEN HERE` | always | `state.partial_regen_anchor = Some(coord)` (Phase 4 — new field) |
| `COPY COORD ({q},{r})` | always | clipboard via `ui.output_mut(\|o\| o.copied_text = format!("{q},{r}"))` |

### 6.2 Sector map — single system

| Item | Enabled when | Action |
|------|--------------|--------|
| `FOCUS SYSTEM` | always | `state.focus_entity(EntityRef::System(id))` |
| `RENAME…` | always | `state.pending_rename = Some(PendingRename { … })` |
| `MOVE…` (arms tool) | always | `state.map_tool = MapTool::MoveSystem; state.drag_system = Some(id)` |
| `DELETE` | always | `BuilderCommand::RemoveSystem { id, before: None, removed_routes: vec![] }` |
| —–-divider—– | | |
| `ADD ROUTE FROM HERE…` | always | `state.map_tool = MapTool::AddRoute; state.pending_route_start = Some(id)` |
| `ADD WORLD` | always | `BuilderCommand::AddWorld { system: id, name: "World-N", result_id: None }` |
| `REGENERATE SYSTEM` | `!pinned_systems.contains(&id)` | `state.generate_system_here(coord, index, None)` |
| `TOGGLE PIN` | always | `pinned_systems.insert/remove(id)` |
| —–-divider—– | | |
| `Open in ▸` (submenu) | always | jumps via `focus_entity`: System, Worlds, Routes, Conflict, Orbital, Archetype, Intel |
| —–-divider—– | | |
| `COPY ID` | always | clipboard |
| `COPY COORD` | always | clipboard |

### 6.3 Sector map — multi-selection (rect-select live OR `selected_systems.len() > 1`)

Shown when the right-click lands on a system already in
`state.selected_systems`, or when no system is hit but the cursor is inside
the live `rect_select` box.

| Item | Enabled when | Action |
|------|--------------|--------|
| `FOCUS FIRST` | always | `state.focus_entity(EntityRef::System(first))` |
| `BULK RENAME…` | always | opens a small dialog (reuse `show_rename_dialog` pattern) with `Sys-{n}` default; calls `apply_bulk_rename` from [system.rs:1030](../builder/src/builder/panels/system.rs#L1030) |
| `PIN ALL` | any unpinned in selection | mutates `pinned_systems` |
| `UNPIN ALL` | any pinned in selection | mutates `pinned_systems` |
| `DELETE ALL` | always | issue N `BuilderCommand::RemoveSystem`; surface failures via `ModalKind::Message`; **must** be confirmation-gated via a small inline "Confirm? [Yes] [No]" submenu — no global modal |
| `ASSIGN PRIMARY FACTION ▸` | factions exist | submenu with one button per faction → `apply_bulk_primary_faction` |
| `FLIP CONTROL STATE ▸` | always | submenu → `apply_bulk_control_state` |
| `RESEED WORLDS` | any non-pinned in selection | `apply_bulk_reseed` |
| `CLEAR SELECTION` | always | `state.selected_systems.clear()` |

(All `apply_bulk_*` helpers already exist in [system.rs:1030-1110](../builder/src/builder/panels/system.rs#L1030-L1110). Promote them to `pub(crate)` so map.rs can call them.)

### 6.4 Sector map — route line

Hit-test: extend `pick_geom` with `hit_route(&sector, screen_pos) -> Option<RouteId>` (see Phase 5 — new geometry helper). Route lines are drawn as poly-lines between hex centres; the helper does point-to-segment distance ≤ `hex_size * 0.18`.

| Item | Enabled when | Action |
|------|--------------|--------|
| `FOCUS ROUTE` | always | `focus_entity(EntityRef::Route(id))` |
| `REMOVE ROUTE` | always | `BuilderCommand::RemoveRoute { id, before: None }` |
| `CYCLE ROUTE TYPE` | always | `BuilderCommand::SetRouteType { id, after: <next variant> }` (new — see Phase 5) |
| `CYCLE STABILITY` | always | `BuilderCommand::SetRouteStability { id, after: <next variant> }` (new) |
| `Open in ROUTES ▸` | always | `focus_entity(EntityRef::Route(id))` |

### 6.5 Sector map — region hex

Resolved via `MapViewCache.lookup.region_for_hex(coord)` (add to
`SectorMapCache` if missing — Phase 5).

| Item | Enabled when | Action |
|------|--------------|--------|
| `FOCUS REGION` | always | `focus_entity(EntityRef::Region(region))` |
| `ERASE FROM REGION` | always | `state.erase_region_hex(&region, coord)` |
| `RECOLOR ▸` | always | submenu of palette entries → `BuilderCommand::SetRegionColor { … }` (new — Phase 5) |
| `RENAME REGION…` | always | inline dialog → `BuilderCommand::RenameRegion { … }` (new — Phase 5) |

### 6.6 System view — star

| Item | Enabled when | Action |
|------|--------------|--------|
| `FOCUS STAR DETAILS` | always | scroll the SYSTEM tab to the Star section (set `state.scroll_target = Some("sys_star_grid")`) — see Phase 0 |
| `CYCLE SPECTRAL CLASS` | star is present | `BuilderCommand::SetStarSpectral { system, after: <next> }` (new — Phase 6) |
| `REMOVE STAR` | star is present | `BuilderCommand::SetStar { system, after: None }` (new — Phase 6) |
| `ADD STAR` | no star | `BuilderCommand::SetStar { system, after: Some(GeneratedStar { … defaults … }) }` |

### 6.7 System view — world (planet)

| Item | Enabled when | Action |
|------|--------------|--------|
| `FOCUS WORLD` | always | `focus_entity(EntityRef::World { system, world })` |
| `RENAME…` | always | inline dialog → `BuilderCommand::RenameWorld { … }` (new — Phase 6) |
| `MOVE ORBIT ▸` | always | submenu of orbits 1..=max → mutates `world.orbit` via new `BuilderCommand::SetWorldOrbit { … }` |
| `DUPLICATE WORLD` | always | `BuilderCommand::AddWorld { … }` then copy fields (compound action) |
| `REMOVE WORLD` | always | `BuilderCommand::RemoveWorld { … }` |
| —–-divider—– | | |
| `Open in WORLD tab` | always | `focus_entity` |
| `COPY ID` | always | clipboard |

### 6.8 System view — empty orbit

| Item | Enabled when | Action |
|------|--------------|--------|
| `ADD WORLD HERE` | always | `BuilderCommand::AddWorld { system, name: "World-N", result_id: None }` then set its orbit (compound) |

### 6.9 System view — background

| Item | Enabled when | Action |
|------|--------------|--------|
| `ADD WORLD` | always | as above, default orbit = `max+1` |
| `REGENERATE SYSTEM` | `!pinned` | `state.generate_system_here(coord, index, None)` |
| `DERIVE ORBITAL ASSETS` | always | call `derive_orbital_assets(sys)` and dispatch `SetOrbitalAssets` + `SetBlockadeReport` |
| `Open in ORBITAL section` | always | jump to the §O1 collapsing header |

## 7. Implementation plan

Phases are sized to each fit within a single Claude run (≈300–800 lines of
diff, ≤6 files, all `cargo test`-clean). Each phase ends green; later
phases assume earlier phases shipped. **Do not bundle phases** — each must
land as its own commit so review can happen incrementally.

### Phase 0 — Prerequisite: embed `SystemView` in SYSTEM tab

The SYSTEM tab today is field-editor only. The system context menu has no
host without the widget.

- Add a new collapsing section "In-system map" at the top of
  [system.rs](../builder/src/builder/panels/system.rs) (above `show_identity_section`).
- Render `gui_core::system_view::SystemView { system: sys, selected: SystemSelection::None, side: 480.0 }`.
- Wire `SystemClick::World(idx)` → `state.selected_world_id = Some(world_id)`
  and `SystemClick::Star` → no-op (scrolls Star header into view via the
  new `scroll_target` field).
- Add `pub scroll_target: Option<&'static str>` to `BuilderState` and apply
  it in `system::show` via `ui.scroll_to_rect` once.
- Tests: `system_view_renders_when_no_worlds`, `world_click_updates_selected_world_id`.

**Acceptance:** opening the SYSTEM tab on a system with worlds shows the
in-system disk; clicking a planet updates the existing world picker.

**Scope guard:** no menu work yet. Stop here, commit, ship.

### Phase 1 — Core menu plumbing (sector, no items yet)

- Add `SectorContextMenu` + `SectorMenuTarget` to
  [types.rs](../builder/src/builder/state/types.rs).
- Add `sector_context_menu: Option<SectorContextMenu>` to `BuilderState`
  (init `None`).
- In [map.rs](../builder/src/builder/panels/map.rs)`::show_hex_map`:
  - On `secondary_clicked` (and not `RegionPaint` mode, and not dragging),
    resolve the target via a new `resolve_sector_context(state, geom, pos)`
    and store the menu.
  - Add a `show_sector_context_menu(ctx, state)` rendered after the map
    canvas, that draws an empty `egui::Area` + frame + a single
    placeholder item `CLOSE` for now.
  - Dismiss on Escape / focus-loss / outside click.
- Add `paint_system_rings` overlay highlighting the context system in
  yellow.

**Tests:** `secondary_click_on_system_opens_menu`,
`secondary_click_dismissed_during_drag`,
`escape_closes_menu`.

**Acceptance:** right-clicking on the map opens an empty menu; clicking
away closes it. No real items yet.

### Phase 2 — Sector menu items for existing commands only

Wire the items in **§6.1 (empty hex)** and **§6.2 (single system)** that
correspond to **existing** `BuilderCommand` variants and helpers. Skip
anything marked "new" — those land in Phase 5.

Specifically include:
- empty hex: `PLACE SYSTEM HERE…`, `PAINT REGION HERE`, `ERASE REGION HERE`, `COPY COORD`
- system: `FOCUS SYSTEM`, `RENAME…`, `DELETE`, `ADD ROUTE FROM HERE…`,
  `ADD WORLD`, `REGENERATE SYSTEM`, `TOGGLE PIN`, `Open in ▸` submenu,
  `COPY ID`, `COPY COORD`

For each item, on activation: run command (or set pending dialog), then
`state.sector_context_menu = None`.

**Tests:** one per item — assert the right `BuilderCommand` lands on
`state.command_log` (or the right pending field is set) after simulated
activation. Reuse the test scaffolding from `map.rs` tests.

**Acceptance:** the most common map workflows are available without
leaving the MAP tab.

### Phase 3 — Multi-selection menu (§6.3)

- Detect multi-selection context in `resolve_sector_context`.
- Promote `apply_bulk_*` helpers in [system.rs:1030-1110](../builder/src/builder/panels/system.rs#L1030-L1110)
  to `pub(crate)` (no behaviour change) so map.rs can call them.
- Add the inline "Confirm? [Yes] [No]" submenu pattern for `DELETE ALL` —
  do **not** use a global modal (would lose menu context).
- Submenus for `ASSIGN PRIMARY FACTION ▸` and `FLIP CONTROL STATE ▸`.

**Tests:** bulk delete confirms before running; submenus disabled when no
factions exist.

### Phase 4 — Partial-regen anchor (§6.1 "START PARTIAL REGEN HERE")  [DONE]

Reuses the existing §G5 partial-regen flow. Adds a transient anchor field:

- `pub partial_regen_anchor: Option<HexCoord>` on `BuilderState`
  ([builder/src/builder/state/mod.rs](../builder/src/builder/state/mod.rs)),
  initialised to `None` in both `new_blank` and
  `session::SessionFile::into_state` so a round-trip drops the anchor.
- The empty-hex schema's `START PARTIAL REGEN HERE` row dispatches
  `SectorMenuAction::StartPartialRegen { coord }` which writes the anchor
  in [panels/map.rs](../builder/src/builder/panels/map.rs).
- While the anchor is live: the MAP toolbox shows a coloured chip
  `partial-regen anchor: (q, r)` plus a `cancel anchor` button, and the
  GENERATION tab's §G5 collapsing header surfaces the hint *"Anchor armed
  at (q, r) — click an opposite corner on the map to complete the rect"*
  with a `Cancel anchor` button above the q/r DragValues.
- The next primary click on any sector hex is consumed by
  `apply_partial_regen_anchor_click(state, click_coord)`. It normalises a
  `PartialRegenRect::from_corners(anchor, click_coord)` into
  `state.partial_regen_rect`, clears the anchor, and returns `true` so
  the click is **not** double-dispatched through the armed `MapTool`.

Implementation deviation vs. the original draft: the spec mentioned a
"GENERATION-tab Partial regen tool" arming a drag; we use the anchor
itself as the arm signal and consume the next primary click instead,
which avoids adding a new `MapTool` variant and keeps Phase 4 inside the
≤4 file budget for `builder/`.

**Tests** (in [panels/map.rs](../builder/src/builder/panels/map.rs)
under `mod tests`):

- `ctx_partial_regen_anchor_defaults_none`
- `ctx_action_start_partial_regen_arms_anchor`
- `ctx_partial_regen_anchor_click_completes_rect` — also asserts the
  corners get normalised regardless of click order.
- `ctx_partial_regen_anchor_click_noop_without_anchor`
- `ctx_partial_regen_anchor_not_in_session_file` — round-trips through
  `SessionFile::{from_state, into_state}` and asserts the anchor is
  dropped, satisfying the §12 in-memory-only invariant.

### Phase 5 — Route + region context (new commands)

This phase introduces new `BuilderCommand` variants. Keep them minimal —
each has a single `before`/`after` field and is undoable.

- New geometry helper `pick_geom.hit_route(&sector, pos) -> Option<RouteId>`
  (point-to-segment, threshold `hex_size * 0.18`). Add unit test.
- Extend `SectorMapCache` with `region_for_hex(coord) -> Option<&str>`.
- New `BuilderCommand` variants:
  - `SetRouteType { id, before, after }`
  - `SetRouteStability { id, before, after }`
  - `SetRegionColor { region, before, after }`
  - `RenameRegion { id, before, after }`
- Wire §6.4 (route) and §6.5 (region hex) menus.

**Tests:** each new command round-trips through `undo`/`redo`; route
hit-test picks the nearest segment.

### Phase 6 — In-system menu (§6.6 – §6.9)

Requires Phase 0.

- Extract a small `system_pick(pos) -> SystemMenuTarget` helper next to
  the embedded `SystemView` widget. Test it like `pick_hex`.
- New `BuilderCommand` variants:
  - `SetStar { system, before, after: Option<GeneratedStar> }`
  - `SetStarSpectral { system, before, after }`
  - `RenameWorld { system, world, before, after }`
  - `SetWorldOrbit { system, world, before, after }`
- Wire the four context schemas.
- `DERIVE ORBITAL ASSETS` reuses
  [orbital.rs:55-60](../builder/src/builder/panels/orbital.rs#L55-L60)
  by extracting its derive-and-dispatch pair into a `pub(crate)` helper.

**Tests:** orbit-cycle wraps correctly; remove-star clears spectral
type; duplicate-world produces unique id.

### Phase 7 — Polish

- Hover-ring overlay (`paint_system_rings`) while menu open.
- Menu clamping to viewport (flip-anchor when overflowing).
- Disabled-item tooltips (`on_hover_text` explaining why).
- Visual divider style matching existing tab headers.
- Keyboard arrow-nav within open menu (`Up`/`Down`/`Enter`/`Escape`) —
  use egui's built-in focus chain.
- Telemetry hook (optional): log menu-item activations via the existing
  `log_*progress` channel for the status bar.

**Tests:** snapshot test of menu render at three cursor positions.

### Phase 8 — Documentation

- Update [GUIDE.md](../GUIDE.md) with a "Right-click on the map" section

## 8. Scope guard checklist per phase

Before opening a PR, the agent must verify:

1. `cargo fmt --all -- --check` passes.
2. `cargo check --workspace --all-targets` passes.
3. `cargo test --workspace` passes.
4. No `unwrap` / `expect` introduced on `state.run` failure paths — every
   error must funnel into `ModalKind::Message`.
5. Diff stays under the file count in the phase header (Phase 0–4: ≤4
   files; Phase 5–7: ≤6 files; Phase 8: docs only).
6. No new dependencies in `Cargo.toml`.
7. No changes outside `builder/` and `docs/` except Phase 5/6 which may
   add a helper to `gui-core/` (geometry hit-tests). Viewer/CLI untouched.
8. Manual smoke: launch `cargo run -p sectorforge-builder`, open a sample
   project, right-click on (a) empty hex, (b) a system, (c) a selection,
   (d) — for Phase 6 — a planet. Confirm the menu opens, items work, and
   the menu dismisses on Escape and outside click.

If a phase grows past these limits, **stop and split it** rather than
bundling. Splits keep the review surface small.

## 10. Edge cases

| Case | Handling |
|------|----------|
| Right-click on a hex outside sector bounds | No menu. `pick_hex` returns None → bail. |
| Right-click during `RegionPaint` (existing erase binding) | Default: paint-erase wins (matches current behaviour). With `Ctrl`: menu opens instead. |
| Sector has 0 systems | Empty-hex menu only; system items never appear. |
| Sector has 0 factions | `ASSIGN PRIMARY FACTION ▸` submenu disabled, tooltip explains. |
| Multi-select rect mid-drag | Suppress menu — `rect_select.is_some()` guard. |
| Pinned system | `REGENERATE SYSTEM` disabled, tooltip: "Unpin first (§S3)". |
| Route hit-test ambiguity (two routes overlap) | Pick the shorter segment-distance; tie → lower `RouteId` lex. |
| Two systems on the same hex (collision dialog already open) | Suppress menu until `pending_collision` clears. |
| Menu open + tab switched via keyboard | Dismiss menu in `BuilderTab::set` (already a single funnel). |
| Menu open + project closed / reloaded | Dismiss on `BuilderState::replace_sector`. |
| Undo while menu open | Menu stays open but its target may be stale; on next render, re-resolve and dismiss if target no longer exists. |
| Right-click on an in-flight ADD-ROUTE pending start | Show only `CANCEL ROUTE` + `Open in ROUTES`. |

## 11. Accessibility

- All menu items must be reachable via keyboard: `Tab` to enter the
  menu, arrows to traverse, `Enter` to activate, `Escape` to dismiss.
  egui's default focus chain handles this if items are real
  `selectable_label`s; verify with a manual keyboard-only pass.
- Disabled items must communicate **why** via `on_hover_text`. Do not
  silently hide items unless they would be nonsensical (e.g. "Add star"
  on a system that already has one).
- Colour is never the only signal — use both colour and a leading symbol
  (`✕` for destructive, `▸` for submenu, `…` for "opens dialog").

---

## 12. Persistence + invariants

- Neither `SectorContextMenu` nor `SystemContextMenu` is serialised. Both
  fields are `#[serde(skip)]` if any serde derive is added in the future.
- `partial_regen_anchor` (Phase 4) is also `#[serde(skip)]`.
- Menu opening cannot move the sector into an invalid state — only item
  activation can, and that goes through `state.run` which already debounces
  validation.

## 13. Telemetry / logging

Optional for v1. If added, route through the existing `log_*progress`
helpers in [cli/common.rs](../src/cli/common.rs) — do **not** introduce
`println!`. A single-line event per activation: `ctx_menu: <schema> :: <item>`.

## 14. Open questions (resolve before Phase 5)

1. Should `CYCLE ROUTE TYPE` be one menu item that rotates through all
   variants, or a submenu with one item per variant? Default: **submenu**
   (better discoverability). Confirm with the user before implementing.
2. Region colour palette — is there an existing palette enum, or do we
   need to extend the regions module? Audit
   [src/regions.rs](../src/regions.rs) before Phase 5.
3. Is there demand for a "Copy as TOML snippet" item on systems and
   routes? Cheap to add once clipboard plumbing is in. Default: defer to
   v2.
4. Should the menu inherit the `theme` setting (`gui_core::palette`) or
   use egui's default popup style? Default: theme-aware (use
   `palette::menu_frame()` if it exists, else fall back to
   `egui::Frame::menu(ui.style())`).
