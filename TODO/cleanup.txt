
  Status Overview
   * Total LOC: ~50,000 Rust.
   * File count: 88 .rs files.
   * Module count: 55 modules in lib.rs.
   * Structure: Heavy data-driven architecture. Large structs in sector_model.rs (~115 fields across core types) suggest
     high memory usage per sector.

  Bloat Indicators
   1. [DONE] Massive UI Component: src/gui/app/mod.rs (2,770 lines) handles state, layout, input, and business logic.
   2. [PARTIAL] String Allocation Bloat: Core DTOs in sector_model.rs and analytics.rs now use Arc<str>.
   3. Primitive Error Handling: 20+ instances of Result<T, String>. Poor for debug/recovery. Refactor → use thiserror
      for all modules (already in Cargo.toml).
   4. [DONE] Parameter Explosion: Main generation and scoring functions now use Parameter Objects (structs).
   5. [DONE] Excessive Derives: 550+ derive attributes. While standard for Serde, many large structs derive Clone, leading to
      expensive deep copies (700+ .clone() calls). Use Arc or references for immutable data.

  Refactoring Strategy
   1. Slab/ECS for Worlds: GeneratedSector owns Vec<GeneratedSystem>, which owns Vec<GeneratedWorld>. Deep nesting →
      hard to traverse/mutate without cloning. Use flat storage with IDs.
   2. Modularize UI: Split src/gui/app/mod.rs by feature (navigation, sector_ops, system_ops).
   3. String Interning: For recurring tags/faction IDs, use SmolStr or interning to reduce heap churn.
   4. Strict Clippy: Existing allow(clippy::too_many_arguments) hides structural issues. Fix root cause, don't suppress.

  Recommended Fixes
   * Immediate: [DONE] Run cargo clippy -- -W clippy::pedantic and fix warnings.
   * Structural: Move inline UI logic from App::update to dedicated widget structs.
   * Performance: Replace String with Arc<str> or &str in hot generation loops.

  Codebase is functional but nearing "maintenance trap" phase due to UI coupling and data nesting. Refactor before
  adding more features.
