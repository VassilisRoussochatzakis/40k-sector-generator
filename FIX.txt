2. Math-accuracy lints (mul_add, hypot)                        [skip]
----------------------------------------------------------------
~55 sites in src/bitmap/mod.rs, ~10 in src/gui/palette.rs.

Lint:    clippy::suboptimal_flops / clippy::imprecise_flops
Fix:     a*b + c            -> a.mul_add(b, c)
         (dx*dx+dy*dy).sqrt -> dx.hypot(dy)
Win:     1 fused op on FMA-capable CPUs; better numerical accuracy.
Why skip:
  Both transforms change the last-bit result. Sector PNGs and JSON
  outputs are byte-deterministic and covered by golden snapshot
  tests. Apply only if you regenerate golden fixtures in the same
  commit.

To apply later:
  cargo clippy --fix --release --allow-dirty -- \
    -W clippy::suboptimal_flops -W clippy::imprecise_flops
  Then: cargo test  (expect snapshot diffs; review each)
        Regenerate fixtures and commit together.

3. Float-loop convergence hazards                              [skip / open]
----------------------------------------------------------------
Sites (clippy::while_float):
  src/bitmap/mod.rs:714, 776, 798, 819, 841, 870, 891, 913, 939, 972
  src/gui/palette.rs:235, 291, 312, 333, 357, 386, 406, 427, 452, 472

Pattern:    let mut f = start;  while f < limit { ...; f += step; }

Risk:       Accumulated FP drift can shift the final iteration count
            by ±1 versus the expected (limit-start)/step. With NaN it
            never terminates.

Correctness/perf fix:
  let steps = ((limit - start) / step).round() as i32;
  for i in 0..steps { let f = start + step * i as f32; ... }

Why skip default:
  Same byte-determinism risk as §2 — different last iteration value
  can shift one pixel. Worth applying per-site if you audit the
  golden output diff for that renderer. Safer in palette.rs (color
  table generation) than in bitmap/mod.rs (pixel raster).

4. HashMap hasher swap                                         [applied]
----------------------------------------------------------------
~500 HashMap/HashSet sites. Default RandomState (SipHash) is
DoS-hardened but slow. The crate has no adversarial input — keys
are typed IDs, hex coords, world-type strings.

Suggested:
  Add dependency:  rustc-hash = "2"     (~5 KB, MIT/Apache)
  Add type aliases in src/lib.rs:
    pub(crate) type FxMap<K,V> = rustc_hash::FxHashMap<K,V>;
    pub(crate) type FxSet<T>   = rustc_hash::FxHashSet<T>;
  Bulk-swap call sites in hot paths first:
    src/generation.rs, src/regions.rs, src/segmentum.rs,
    src/economy.rs, src/route_control.rs, src/power_projection.rs

Determinism rule (already followed): never iterate a hash map for
output. Output writers must sort keys first. The crate already
honours this; if you ever break the rule a Fx-hashed map will make
the bug visible immediately.

Expected win: 10-40% on map-heavy passes. Bench src/segmentum.rs
stitch and src/search.rs evaluate first to confirm.

Applied this pass:
  Dep:  rustc-hash = "2" added to Cargo.toml.
  Aliases (src/lib.rs):
    pub(crate) type FxMap<K,V> = rustc_hash::FxHashMap<K,V>;
    pub(crate) type FxSet<T>   = rustc_hash::FxHashSet<T>;
  Swapped (internal lookup-only structures; no iter-to-output):
    src/power_projection.rs
      build_adjacency return:  HashMap -> FxMap (with_capacity hint
        seeded from sector.systems.len())
      bfs_distances visited:   HashSet -> FxSet
      bfs_distances adj param: HashMap -> FxMap
      (BTreeMap<FactionId, BTreeMap<SystemId, f32>> output map
       intentionally kept — it is the Serialize'd public DTO
       PowerProjectionMap.by_faction, so JSON ordering MUST stay
       deterministic.)
    src/render.rs
      events_by_system / events_by_world: HashMap -> FxMap
        (per-value Vec is sorted before consumption; map itself
         is lookup-only via .get(key))
      at / region_at: HashMap -> FxMap (lookup-only via .get)
      empty_map: HashMap::new() -> FxMap::default()
Scope of swap (intentionally narrow):
  - Only the explicitly hot, internal-lookup sites are converted.
  - heatmap::compute_rgb returns HashMap<SystemId, HeatCellRgb> and
    is used as `&HashMap<...>` across bitmap.rs and svg_export.rs —
    swapping would cascade through public-ish render plumbing. Left
    as HashMap; consumer code only does .get(sys.id) lookups, so
    Sip-vs-Fx is the only difference and a future pass can flip the
    return type along with all 6 callsites in one go.
  - Other crate-wide HashMap sites (importance.rs grouping aggregator,
    search.rs FactionIndex, bitmap/svg_export tints, worlds.rs config
    maps) were left alone — most are cold or load-once.
Verification:
  - cargo test --lib  : 162 passed.
  - cargo test        : full suite green (svg_export, validation,
    proptest, doc-tests all pass).
  - Determinism check: ran `cargo run --release --bin sectorforge --
    generate --project examples/m42_project` twice and
    `diff -rq` on the full out/ tree reported no differences.
    Confirms the Fx-hashed maps are never iterated for output.

10. Drop a serde feature                                       [skip / documented]
----------------------------------------------------------------
Cargo.toml: serde = { ..., features = ["derive", "rc"] }

VERIFIED REQUIRED. Removing "rc" produces 200+ errors of the form
`Arc<str>: serde::Deserialize<'de> is not satisfied` because the
DTOs in src/sector_model.rs, src/ids.rs (FactionId/SystemId/WorldId
wrap Arc<str>), and others derive Serialize/Deserialize on Arc<str>
fields. The "rc" feature gates serde's Serialize/Deserialize impl
for Rc<T> / Arc<T>, including Arc<str>.

Keep "rc". Do not revisit unless DTOs migrate off Arc<str> entirely.

13. Parallelism                                                [bench]
----------------------------------------------------------------
Generation, search enumeration, and segmentum compose are the three
embarrassingly-parallel passes:

  src/search.rs   evaluate_all over candidate seeds (independent)
  src/segmentum.rs compose loop over child sectors (independent)
  Bitmap rendering of multiple sectors

rayon would parallelise each in one line:
  candidates.par_iter().map(|seed| evaluate_all(...)).collect()

Determinism: rayon preserves iteration order in collect, so output
is unchanged. Risk: any shared mutable state (RNG, caches). The
crate currently threads `ChaCha8Rng` by value — safe.

Bench: cargo bench --bench generation before/after.
