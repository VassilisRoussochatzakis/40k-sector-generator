================================================================================
0. WHY (so you can make judgment calls)
================================================================================

Before the split, the builder shipped inside `sectorforge-gui` under `gui/src/builder/`
(~8.1k lines, 37% of the GUI crate). Coupling to the rest of the GUI was
exactly 2 symbols:
  - `gui/src/builder/preview.rs`        uses `crate::jobs::{spawn_job, JobHandle}`
  - `gui/src/builder/panels/map.rs`     uses `crate::palette::{...}`

The viewer `App` struct (`gui/src/app/mod.rs`) holds ZERO builder state. No
non-builder code in `gui/src/` references `BuilderState`, `BuilderWorkspace`,
or any `crate::builder::*` symbol. `gui/src/lib.rs:6` is the only top-level
wire-in (`pub mod builder;`).

BUILDER_REQS.txt §G6 / Phase B host wiring had not landed before the split.
The split landed first; the current workspace tab strip is owned by
`sectorforge-builder` / `BuilderApp`, not mounted inside `sectorforge-gui`.

Goal: three crates after this work:
  1. `sectorforge`             (existing lib + CLI bin, unchanged)
  2. `sectorforge-gui-core`    (NEW shared widget/util crate)
  3. `sectorforge-gui`         (existing crate, viewer/editor only, slimmed)
  4. `sectorforge-builder`     (NEW crate, owns builder + thin App)

Communication path between viewer and builder: project-directory file
handoff. Builder saves a project; viewer is launched with
`sectorforge-gui --project <dir>` and auto-reloads via the existing
FileWatcher / `load_sector_json` path. No IPC, no shared memory.

    use eframe::egui;
    use sectorforge::sector_model::GeneratedSector;
    use crate::builder::{BuilderState, BuilderWorkspace};

    pub struct BuilderApp {

    impl BuilderApp {

        pub fn with_initial_state(state: BuilderState) -> Self {
            Self { workspace: BuilderWorkspace::new(state) }
        }

    impl eframe::App for BuilderApp {
        fn update(&mut self, ctx: &egui::Context, _frame: &mut eframe::Frame) {
            // Apply theme — copy from gui/src/app/ui_helpers.rs::apply_theme
            // and either move into gui-core or duplicate here (it's small).

            // Render active panel for workspace.active_mut()

  IMPORTANT: do NOT try to lift the whole viewer `App` shell. The builder
  bin should be a *thin* host that mounts the existing builder panels via
  the existing `panels::nav` router. Look at:
    builder/src/builder/panels/nav.rs
    builder/src/builder/panels/mod.rs
  and call whatever router function they expose, passing
  `self.workspace.active_mut()`.

  If `nav.rs` calls into helpers that lived in `gui/src/app/*` (theme,
  layout, top-bar), you have three choices, in order of preference:
    (a) Move the helper into gui-core (best when it's pure-egui chrome).
    (b) Duplicate the helper into builder/src/app.rs (best when it's tiny
        and tightly bound to viewer state).
    (c) Lift the helper into a third "shell" crate (only if multiple
        helpers and meaningful reuse — likely overkill).

  Create builder/src/main.rs (model on gui/src/main.rs):

    use std::process::ExitCode;
    use camino::Utf8PathBuf;
    use clap::Parser;
    use sectorforge_builder::BuilderApp;
    use sectorforge_builder::builder::{open_project, new_project, NewProjectOptions};

    #[derive(Debug, Parser)]
    #[command(name = "sectorforge-builder",
              about = "Interactive builder for 40k sectors")]
    struct Cli {
        /// Project directory to open. If omitted, launches with a blank workspace.
        #[arg(long)]
        project: Option<Utf8PathBuf>,
    }

    fn main() -> ExitCode {
        let cli = Cli::parse();
        let app = if let Some(dir) = cli.project {
            match open_project(&dir) {
                Ok(state) => BuilderApp::with_initial_state(state),
                Err(e) => {
                    eprintln!("failed to open project '{dir}': {e}");
                    return ExitCode::from(2);
                }
            }
        } else {
            BuilderApp::new()
        };
        let opts = eframe::NativeOptions {
            viewport: egui::ViewportBuilder::default()
                .with_inner_size([1400.0, 900.0])
                .with_title("sectorforge — builder"),
            ..Default::default()
        };
        match eframe::run_native(
            "sectorforge-builder",
            opts,
            Box::new(move |_cc| Ok(Box::new(app))),
        ) {
            Ok(()) => ExitCode::SUCCESS,
            Err(e) => { eprintln!("gui error: {e}"); ExitCode::from(1) }
        }
    }

  NOTE: `open_project` / `new_project` signatures may differ — read
  builder/src/builder/project_io.rs and adapt. The existing wizard
  (`gui/src/app/...` G6 path) probably required extra args; if the binary
  needs a `NewProjectOptions`, default it.
